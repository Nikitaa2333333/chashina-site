# Сайт Оксаны Чащиной — врач-косметолог, превентивная медицина

Персональный лендинг (одна страница + служебные в планах). Дизайн скопирован
с **integratedbio.com** («биолюминесцентная лаборатория»: тёмно-зелёный канвас,
один лаймовый акцент, единственное начертание 400, mono-подписи) и адаптирован
под бьюти-тематику. Вся типографика и отступы — токенами.

## Стек и запуск

- **Astro 5**, чистый CSS (без Tailwind), ванильный TS в `<script>` секциях.
- Дев-сервер: `npx astro dev --host 127.0.0.1 --port 4331`
  (без явного `--host` порт наружу не отдаётся — правило из глобального CLAUDE.md).
- Открывать: http://127.0.0.1:4331/
- Деплоя пока нет. Прод-сборка: `npx astro build` → `dist/`.

## Дизайн-система

Всё в `src/styles/global.css`, менять токены — не значения в компонентах.

**Цвета:** `--ink #222f30` (тёмный канвас/текст, НЕ чёрный — зелёная нота),
`--lime #cef79e` (единственный акцент: чипы-стрелки, точки тегов, `<mark>`),
`--lime-2 #a7e26e` (hover), `--bone #f7f7f5` (светлый канвас), `--paper #fff`,
`--sea #445e5f` (границы на тёмном, 4-я плашка), `--sage #c9cbbe` (hairline на
светлом), `--tissue #e4e3e3`, `--frost #eee`, `--void #000` (только якоря).

**Типографика:** одно начертание 400 на всём сайте. Иерархия — размером и
отрицательным трекингом (крупнее кегль → сильнее трекинг, до −0.03em).
Sans — Inter Tight (замена Aspekta, у которой нет кириллицы); mono — Roboto Mono
для СЛУЖЕБНОГО: теги секций, навигация, кнопки, подписи — всегда uppercase
через класс `.mono`. Шкала — резиновые токены `--text-hero … --text-caption`.

**Жёсткие правила** (из глобального CLAUDE.md пользователя, зашиты предохранителем в CSS):
- Никакого bold/italic внутри наборного текста. Акцент — только `<mark>` (лаймовая
  подложка), фраза должна влезать в одну строку, 1–2 на секцию.
- Никаких буллитов и разделительных линий в перечислениях — только ритм.
- Текст только контрастный: на тёмном чистый `#fff`, на светлом `--ink`.
  Не приглушать серым/прозрачностью (плейсхолдеры форм — исключение).
- Мера строки токенами в `ch` на самом элементе (`--measure-*`), см. SPACING.md.
- Тени запрещены — глубина цветом поверхности и hairline-границами.
- Лайм не бывает фоном крупных поверхностей и основных кнопок.

**Отступы:** пульт в `:root` (`--page-max 1520`, `--gutter`, `--section-gap` —
это ПОЛОВИНА дыры между секциями). Подробности и ловушки — в SPACING.md.

**Скругления:** кнопки 8, шапка 12, карточки 20, крупные плашки 24, пилюли 9999.

**Фирменные приёмы:** тёмные секции — скруглённые плашки (`border-radius: 24px;
margin-inline: 12px`) на светлом канвасе; тег секции — белая пилюля с лаймовым
квадратиком; кнопка — пара «тёмная пилюля + лаймовый чип-стрелка» (BtnPair);
глассморфизм в шапке и на фото-плашках слайдера; изинг `--ease cubic-bezier(0.16,1,0.3,1)`.

## Секции главной (порядок в index.astro)

1. **Хиро** — скролл-сцена (sticky, трек 260svh): на старте только вырезанное
   фото по центру на светлом фоне; по скроллу «Оксана» выезжает слева, «Чащина»
   справа (за фото), затем снизу проявляются подзаголовок + отстройка + BtnPair.
   Фон — canvas `[data-hero-mol]`: ~46 дрейфующих «молекул» со связями
   (плексус), каждая пятая лаймовая. Останавливается вне вьюпорта.
2. **Подход / Две половины одной работы** — тёмная плашка: колонки
   «01. Снаружи / 02. Изнутри» (без карточек, чистая типографика), вывод с `<mark>`.
3. **Как строится работа** — заголовок «Почему я не начинаю с лифтинга», три
   полноэкранные панели-ступени (лайм/тёмная/серая, edge-to-edge, без радиусов)
   + SVG-линия прогресса.
4. **Принципы / Что для меня важно** — три редакционные строки (заголовок
   слева, текст справа), у каждой по два абзаца. Секцию убирали 07.08, вернули
   05.09 с переписанным текстом Оксаны (см. лог).
5. **Манифест** — центрированная крупная фраза с круглыми фото-вставками
   размером с букву (`.statement__dot`). Референс: supplement-сайт. Сейчас в
   кругах фото-заглушки, заменить на генерации (PROMPTS.md §8).
6. **Аппаратные методы** — горизонтальный скролл-слайдер `[data-mscroll]`:
   sticky-сцена, 4 вертикальные фото-плашки (art/method-01..04) листаются по
   скроллу, справа градиентное затухание (гаснет к концу). Низ каждой плашки
   «утопает» в стекле: размытая копия фото с маской (`filter`, НЕ backdrop —
   backdrop-filter на движущемся лагает). Мобайл/reduced-motion — нативный свайп.
   После — «Чего я больше не делаю».
7. **SMAS/птоз** — тёмная плашка, текст + фоновое видео ripple.mp4.
8. **Инъекционные методы** — 4 задачи сеткой, закрывашка с `<mark>`.
9. **Зоны, которые выдают возраст** — 3 колонки (шея/подбородок/кисти).
10. **Не с крема** — видео serum.mp4 + текст, кнопка «Читать статьи» (пока #).
11. **Видео** `#video` — «Как я объясняю»: 4 вертикальных ролика из инстаграма
    (`public/video/reels/reel-01..04`). Постер — отдельная `<img loading="lazy">`,
    у `<video>` только `data-reel` и `preload="none"`: файл грузится по клику,
    играет всегда один. Десктоп — ряд из четырёх, ≤900px — лента со свайпом.
    Пульт свой (`.reels__ui`), нативный `controls` не включаем: пуск/пауза,
    полоса с перемоткой, звук, фуллскрин — стеклянная плашка внизу карточки.
12. **Соцсети** — тёмная плашка, 3 строки-ссылки (TG/VK/Дзен) с лайм-ховером.
13. **Пресса** — 6 публикаций (РБК, ТАСС, Газета.ру, Flacon, U Magazine, Beautyhack).
14. **Обо мне** — текст (рыба!) + замыкающая мысль, `<details>` «Образование
    и квалификация» с реальными данными из структуры.
15. **Запись** `#contact` — тёмная плашка с формой: имя, телефон, комментарий,
    чекбокс согласия, submit. **Бэкенда нет** — форма визуальная.
16. **Футер** — тёмный, statement + навигация + соцсети, гигантский вордмарк
    «Чащина», обязательная строка «Имеются противопоказания…».

Все скролл-механики живут в одном `<script>` в index.astro и уважают
`prefers-reduced-motion` (статичное финальное состояние).

## Блог из телеграм-канала (/blog/)

Отдельная вкладка (решение заказчика: пока НЕ смешивать с будущими «Статьями»,
объединить можно позже). Список — `/blog/`, пост — `/blog/<slug>/`. Ссылки
«Блог» — в шапке и футере; все якоря в них теперь `/#…`, чтобы работали
с подстраниц. Футер вынесен в `components/Footer.astro`.

**Данные:** `src/data/telegram-posts.json`. Сейчас там РЫБА
(`placeholder: true` — на странице списка видна пометка). Реальные посты
заливает `npm run tg` (= `scripts/import-telegram.mjs`) из выгрузки
Telegram Desktop: папку с `result.json` и `photos/` положить в
`telegram-src/` (в git не идёт). Скрипт перепишет JSON целиком и разложит
фото в `public/photos/tg/` (webp ≤1200px через sharp из зависимостей Astro).

**Правила отбора постов** (зашиты в скрипт, ручки — флагом `--min-chars`):
- только информационные: короче 180 знаков не берём (анонсы, поздравления);
- опросы и сервисные сообщения — мимо;
- пост, где главное медиа — видео/кружок/гифка, не берём целиком;
- фото-альбом собирается в карусель (в выгрузке это сообщения без текста
  следом за постом); видео-участник альбома выбрасывается, пост остаётся;
- жирный/курсив телеграма намеренно плющится в обычный текст (правило одного
  начертания), ссылки сохраняются, хэштеги выбрасываются.

**Вёрстка:** список — сетка карточек (пост без фото — тёмная плашка для
ритма, у каруселей стеклянный счётчик «N фото»); страница поста — узкая
колонка, карусель на scroll-snap со стрелками-чипами и счётчиком (свайп
и reduced-motion уважаются), внизу ссылка на пост в канале + BtnPair
на `/#contact`. Выгрузка текстов (`npm run texts`) блог НЕ трогает —
она читает только dist/index.html; сверка постов с Оксаной — прямо
по каналу, источник правды там.

## Тексты сайта на сверку (пайплайн перенесён из ktm-site)

Оксана вычитывает контент не в вёрстке, а в Google-документе. Поэтому весь
видимый текст страницы дублируется выгрузкой `docs/тексты-сайта.md`.

- Генерация: **`npm run texts`** (= `astro build` + `scripts/extract-texts.mjs`);
  текст берётся из собранного `dist/index.html`, то есть дословно совпадает с сайтом.
- **Правило: поменял текст на странице → сразу перегенерировать выгрузку и
  закоммитить вместе с правкой.** Выгрузка не должна отставать от кода.
- Файл выгрузки руками НЕ редактировать — источник правды по тексту всегда код.
- Формат: каждая секция — раздел «NN. Тег — Заголовок» с меткой `*(секция: #id)*`,
  по ней правка клиента находит место в вёрстке. `<mark>` сохраняется тегом;
  `*(кнопка)*`, `*(меню)*`, `*(поле: …)*` — служебный курсив.
- Секция без своего тега и заголовка (`.steps`, `.mscroll`) приклеивается к
  предыдущей — своим разделом она читается обрывком. Список секций и запасные
  названия — в `SECTION_NAMES` внутри скрипта; незнакомая секция печатает
  предупреждение, а не молча теряет название.

### Заливка в Google Docs

Рядом с `.md` скрипт кладёт `docs/тексты-сайта.html` (в git не хранится).

- **Заливать в Drive нужно именно HTML** (`contentMimeType: text/html`). Markdown
  Drive тоже принимает, но выбрасывает `<mark>` — фирменная заливка теряется.
  Через HTML доезжает всё: маркер, таблицы, уровни заголовков, служебный курсив.
- **После заливки — обязательная сверка**: вычитать документ обратно, положить
  текст файлом и прогнать `node scripts/verify-gdoc.mjs <файл>`. Ноль пропаж =
  документ совпал дословно. Это не формальность: заливка **рвётся на середине
  незаметно** — документ выглядит целым, а половины текста нет.
- Обновления заливаются НОВЫМ документом (у Drive-коннектора нет апдейта файла) —
  старый лучше удалить руками, чтобы у Оксаны не было двух версий.
